# Building exip

exip is built with CMake 3.16 or later (the presets need 3.21). The library is ISO C99
(C11 where available) and builds with GCC, Clang, AppleClang, MSVC (Visual Studio 2015 or
later), mingw-w64, arm-none-eabi and the Arduino/ESP32 toolchains. The configuration is
compiler-neutral: CMake options, or a header for builds without CMake.

## Quick start

```sh
cmake --preset gcc-debug              # or: cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build --preset gcc-debug
ctest --preset gcc-debug
cmake --list-presets                  # all presets
```

Requirements for the test suites: the Check unit test library (`check`, found with
pkg-config) and valgrind for the memory-check variants (Linux). zlib enables EXI
compression in host builds.

## Presets (CMakePresets.json)

Binary directories are `build/<preset>`.

| Preset | What it builds | Tests (`ctest --preset`) |
|---|---|---|
| `gcc-debug`, `gcc-release`, `clang-debug`, `clang-release` | host build: libraries, exipg, examples, test suites | all suites, valgrind variants (Linux), golden tests |
| `msvc` (Windows hosts) | Visual Studio generator; build presets `msvc-debug`, `msvc-release` | smoke: help, round trip, artifact check |
| `mingw-cross` | Windows executables with mingw-w64 on Linux | smoke: artifact check |
| `small-host` | the `small` configuration on the host | smoke |
| `contiki-compat` | the former contiki profile: `small` with the d_mem allocator | smoke |
| `riot-compat` | the former riot profile: `host` with debug off and smaller hash tables | smoke |
| `arm-none-eabi-small` | Cortex-M4 bare metal, `small`, MinSizeRel, libraries only; build preset `arm-none-eabi-small-size` prints the size report | none |

Two test suites report known valgrind errors (`check_valgrind_check_exip` 2,
`check_valgrind_check_strict_grammar` 4 with GCC Debug); the CI excludes them and fails if
the counts grow. The CI (`.github/workflows/build-matrix.yml`) runs every preset.

## Build switches

| Option | Default | Meaning |
|---|---|---|
| `EXIP_BUILD_TOOLS` | ON, OFF for bare metal (`CMAKE_SYSTEM_NAME Generic`) | exipg, the schema compiler |
| `EXIP_BUILD_EXAMPLES` | as `EXIP_BUILD_TOOLS` | exipe, exipd |
| `EXIP_BUILD_TESTS` | ON, OFF when cross-compiling | test suites, golden and smoke tests (the mingw preset turns it on for the artifact check) |
| `EXIP_VALGRIND` | AUTO | AUTO: valgrind variants when valgrind is found (not on macOS); ON requires it; OFF |
| `EXIP_USE_ZLIB` | AUTO | AUTO: debug-on native build with zlib found; ON requires zlib; OFF |
| `EXIP_HARDENING` | ON | `_FORTIFY_SOURCE`, stack protector, `-z relro/now` (not on Apple) for native UNIX GCC/Clang builds |
| `EXIP_WARNINGS_AS_ERRORS` | ON | `-Werror` / `/WX` |

`SKIP_TESTS` and `SKIP_VALGRIND` still work and print a deprecation message.

Warnings: GCC and Clang use `-Wall -Wextra -Wpedantic`; MSVC uses `/W4 /utf-8` with C4244,
C4267 (narrowing conversions) and C4127 (constant conditions from the configuration
switches) disabled, and `/std:c11` from Visual Studio 2019 16.8.

## Configuration

`include/exipConfig.h` assembles the configuration, first definition wins:

1. macros on the compiler command line;
2. `EXIP_USER_CONFIG_FILE`, a header with the application's settings, for builds without
   CMake (Arduino and ESP-IDF builds get `exip_arduino_config.h` automatically, see below);
3. `exip_build_config.h`, generated by CMake into `<build>/generated/include` from the
   `EXIP_CFG_*` options; the CMake targets define `EXIP_HAVE_BUILD_CONFIG=1`;
4. `include/exipConfigDefaults.h`: a default for every setting, and `#error` checks of the
   result.

`EXIP_CFG_PRESET` (`host` or `small`) seeds the `EXIP_CFG_*` cache options; each can then be
set on its own:

| Option | host | small | Macro |
|---|---|---|---|
| `EXIP_CFG_DEBUG` | ON | OFF | `EXIP_DEBUG` (the test suites need ON) |
| `EXIP_CFG_DEBUG_LEVEL` | INFO | INFO | `EXIP_DEBUG_LEVEL` (`EXIP_LOG_INFO`, `_WARNING`, `_ERROR`) |
| `EXIP_CFG_DEBUG_MODULES` | none | none | `DEBUG_STREAM_IO`, `DEBUG_COMMON`, `DEBUG_CONTENT_IO`, `DEBUG_GRAMMAR_GEN` |
| `EXIP_CFG_ALLOCATOR` | libc | libc | libc, `dmem` (4 KB static heap, `src/common/alloc`) or `custom` with `EXIP_CFG_MALLOC`, `_REALLOC`, `_FREE`, `_ALLOCATOR_HEADER` |
| `EXIP_CFG_INTEGER_BITS` | 64 | 32 | `EXIP_INTEGER`, `EXIP_UNSIGNED_INTEGER`, float mantissa |
| `EXIP_CFG_INDEX_BITS` | size | 16 | `EXIP_INDEX` (size = `size_t`) |
| `EXIP_CFG_SMALL_INDEX_BITS` | size | 8 | `EXIP_SMALL_INDEX` |
| `EXIP_CFG_HASH_TABLES` | ON | OFF | `HASH_TABLE_USE` |
| `EXIP_CFG_HASH_TABLE_INITIAL`, `_MAX` | 6151, 32000 | 53, 3000 | `INITIAL_HASH_TABLE_SIZE`, `MAX_HASH_TABLE_SIZE` |
| `EXIP_CFG_PROFILE_DEFAULT` | OFF | OFF | `EXI_PROFILE_DEFAULT` |
| `EXIP_CFG_VALUE_CROSSTABLE`, `_BUILTIN_GRAMMARS` | ON | ON | `VALUE_CROSSTABLE_USE`, `BUILD_IN_GRAMMARS_USE` (OFF with the profile default) |
| `EXIP_CFG_IMPLICIT_CONVERSION` | ON | OFF | `EXIP_IMPLICIT_DATA_TYPE_CONVERSION` |
| `EXIP_CFG_GRAMMAR_TABLE`, `_SIMPLE_GRAMMAR_TABLE` | 300, 75 | 40, 55 | `DEFAULT_GRAMMAR_TABLE`, `DEFAULT_SIMPLE_GRAMMAR_TABLE` |
| `EXIP_CFG_COMPRESSION_TRACE` | OFF | OFF | `EXIP_COMPRESSION_TRACE` (compression decoder traces to stderr) |

Legacy names: `boolean`, `INFO`/`WARNING`/`ERROR` and `STRICT` are still defined, except on
Windows (they clash with `windows.h`), under `ARDUINO` (`boolean`) and when
`EXIP_NO_LEGACY_BOOLEAN`, `EXIP_NO_LEGACY_LOG_LEVELS` or `EXIP_NO_LEGACY_STRICT` is defined.
New code uses `exip_bool`/`EXIP_TRUE`/`EXIP_FALSE`, `EXIP_LOG_*` and `EXIP_STRICT`.

### Former platform profiles

The per-compiler `exipConfig.h` files under `platform/`, the GNU make build
(`platform/gcc/Makefile`) and the Visual Studio 2010 notes are gone.
`EXIP_PLATFORM_PROFILE` still works for now and prints a deprecation message:

| `EXIP_PLATFORM_PROFILE` | Equivalent | Preset |
|---|---|---|
| `pc` | `EXIP_CFG_PRESET=host` | `gcc-debug` and friends |
| `mingw` (and `vs2010`) | `host`, built with the mingw-w64 toolchain | `mingw-cross` |
| `contiki` | `small` and `EXIP_CFG_ALLOCATOR=dmem` | `contiki-compat` |
| `riot` | `host`, `EXIP_CFG_DEBUG=OFF`, hash tables 1021/8192 | `riot-compat` |

The settings are the same as with the old headers (checked by comparing the preprocessed
macros and the type sizes); Contiki's float exponent is now a signed `int8_t` (was `char`,
unsigned on ARM).

## Toolchains

- `cmake/toolchains/mingw-w64-x86_64.cmake`: Windows executables on Linux.
- `cmake/toolchains/arm-none-eabi.cmake`: bare-metal ARM (`gcc-arm-none-eabi` and
  `libnewlib-arm-none-eabi` packages). `EXIP_ARM_CPU_FLAGS` selects the core (default
  `-mcpu=cortex-m4 -mthumb -mfloat-abi=soft`); the libraries use function/data sections for
  `--gc-sections`.
- MSVC: open the folder in Visual Studio or use the `msvc` preset.
- `size_report` target: text/data/bss per library with the toolchain's `size`.

## Install and use

```sh
cmake --install build/gcc-release --prefix /opt/exip
```

installs the five static libraries (`libexip.common`, `.streamIO`, `.grammar`,
`.contentIO`, `.grammarGen`), `exipg`, and the headers in `include/exip`, including the
generated `exip_build_config.h`. Applications compile with `-I<prefix>/include/exip
-DEXIP_HAVE_BUILD_CONFIG=1`, so that they see the configuration the libraries were built
with. C++ applications include `exip.h` (API in namespace `exip`). Shared libraries and
`find_package(exip)` are not provided yet.

## Static grammars

`exipg -static` compiles an XML schema (itself EXI-encoded) into C structures, so that a
device does not need to load schemas at run time:

```sh
exipg -static -pfx=my_ -schema=my-xsd.exi my_schema.c
```

The read-only tables are `const` and stay in flash; the string and grammar tables the
library extends while processing stay writable (`-static=<uri>:<ln>:<pfx>:<grammars>`
reserves room for such extensions).

## Arduino and PlatformIO

Supported: 32-bit ARM and ESP32 boards (Arduino Due, Nano 33 BLE, Raspberry Pi Pico,
ESP32). 8-bit AVR boards (Uno, Mega) are not supported: the static grammars and the string
tables do not fit, and their C library has no `strtoll` and no 64-bit `printf`.

### Configuration

`include/exipConfig.h` selects `include/exip_arduino_config.h` whenever `ARDUINO` or
`ESP_PLATFORM` is defined and there is no CMake build configuration. The library and the
sketch are compiled with different flags, so the configuration must come from the headers
themselves; otherwise the sketch could see other type widths than the library.

The Arduino settings are lean: no debug output, 32-bit integers, 16-bit indexes, 8-bit
grammar rule indexes, no hash tables, no implicit type conversion, small initial grammar
tables, none of the legacy names (`boolean`, `INFO`/`WARNING`/`ERROR`, `STRICT`). Every
setting is guarded by `#ifndef`, so a single one can be changed with a build flag (PlatformIO
`build_flags = -DEXIP_DEBUG=ON`). With `EXIP_DEBUG=ON` the debug output goes to
`int exip_debug_printf(const char* format, ...)`, which the application provides (the
example forwards it to `Serial`). `-DEXIP_NO_ARDUINO_CONFIG` turns the selection off.

Schema loading at run time (grammarGen) is not part of the Arduino library. Compile the
schema on the host with `exipg -static` and add the generated C file to the sketch: its
read-only tables are `const` and stay in flash.

### C++

In C++, `exip.h` declares the API in namespace `exip` with C linkage, because exip's `String`
type would clash with Arduino's `String` class: write `exip::String`, `exip::serialize`,
`exip::parse`, `exip::EXIP_OK`. The macros stay global. Values of type `exip_bool` are
`exip::EXIP_TRUE` / `exip::EXIP_FALSE` (C++ does not convert `0`/`1` to an enum). exip's
`TRY` macro names `EXIP_OK` without the namespace; the example uses its own `CHECK` macro.

### PlatformIO

`library.json` at the repository root describes the library (sources of the common,
streamIO, contentIO and grammar modules). In a project:

```ini
lib_deps = https://github.com/nhenehan/exip.git
```

`examples/platformio/platformio.ini` builds the example against this checkout:

```sh
cd examples/platformio
pio run -e due          # or nano33ble, pico, esp32dev
```

### Arduino IDE / arduino-cli

The Arduino library format needs all headers in `src/`. A CMake build directory produces
the bundle:

```sh
cmake -S . -B build
cmake --build build --target arduino_bundle_zip   # build/arduino/exip-arduino-<version>.zip
arduino-cli compile -b arduino:sam:arduino_due_x --library build/arduino/exip \
    build/arduino/exip/examples/ExipRoundTrip
```

In the Arduino IDE: Sketch > Include Library > Add .ZIP Library.

### Example

`examples/arduino/ExipRoundTrip` encodes a small document without a schema into a RAM
buffer (37 bytes of EXI for 60 bytes of XML), decodes it and prints the events to `Serial`.

### Size

The example compared with a blank sketch that only uses `Serial`, built 2026-10-11 (exip
0.5.5). Flash includes initialised data; RAM is static data and bss. The
heap is extra: the example's peak is about 10 KB on a 64-bit host build with the Arduino
settings (less with 32-bit pointers).

| Board | Tool | Flash: blank / with exip / exip | RAM: blank / with exip / exip |
|---|---|---|---|
| Arduino Due (SAM3X8E) | PlatformIO atmelsam 9.0.0 | 11,844 / 54,292 / **42,448** | 3,764 / 8,016 / **4,252** |
| Arduino Due (SAM3X8E) | arduino-cli 1.5.1, arduino:sam 1.6.12 | 11,952 / 55,232 / **43,280** | 3,728 / 7,980 / **4,252** |
| ESP32 DevKit | PlatformIO espressif32 7.1.3 | 267,009 / 308,093 / **41,084** | 21,464 / 24,624 / **3,160** |
| ESP32 | arduino-cli 1.5.1, esp32:esp32 3.3.12 | 268,748 / 311,432 / **42,684** | 22,116 / 25,276 / **3,160** |

Most of exip's static RAM (about 3 KB) is the part of the built-in EXI options grammar that
the library extends while it works (the string tables, the grammar table); its read-only
tables are `const`. For the Due, PlatformIO's own "RAM" figure counts only
`.bss`; the table adds the `.relocate` (initialised data) section.

Nano 33 BLE (PlatformIO nordicnrf52) and Raspberry Pi Pico (PlatformIO raspberrypi, Arduino
Mbed core) build the example from `examples/platformio` without exip warnings; their sizes
were not measured against a blank sketch.
